## 🏗️ Engineering Mindset

> I approach backend systems the way infrastructure teams do — reliability, observability, and horizontal scalability are first-class constraints from day one, not features added later.

<table>
<tr>
<td valign="top" width="55%">

**Principles I build by**

- API contracts are the product — version, document, and never break them silently
- Every query that goes to production has an `EXPLAIN ANALYZE` behind it
- Services will fail — design for graceful degradation and automatic recovery
- Distributed state is hard — Redis is a cache, not a source of truth
- Logging + metrics + health checks are non-negotiable in any live environment
- Schema migrations are code — reviewed, versioned, and tested before deploy

</td>
<td valign="top" width="45%">

**What I optimize for**

```
Latency      →  P99 matters more than average
Throughput   →  Async I/O, connection pooling
Reliability  →  Retry logic, idempotent endpoints
Security     →  Zero-trust inputs, parameterised SQL
Scalability  →  Stateless services, queue-backed workers
Visibility   →  Structured logs, error tracing
```

</td>
</tr>
</table>
